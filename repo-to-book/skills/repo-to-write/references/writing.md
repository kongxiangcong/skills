# 按确认版大纲与章内素材成稿

写作阶段围绕同一个专题目录工作：读取根目录的 `outline.md` 和每章的 `chapters/<id>/materials.md`，将正式正文写入 `chapters/<id>/manuscript.md`。文风、标题与术语规则统一见 [writing-style.md](writing-style.md)。

## 一、遵守 `outline.md` 的两层约定

动手写正文前，先读 `outline.md`：

1. **全书约定**：确认目标读者、读完应掌握的能力、整体叙述顺序、术语偏好、例子放置规则（例如“只在格式解释之后给例子”）与图表要求。
2. **逐章大纲**：严格按已确认的章数、章序和小节顺序写作。**不拆章、不合章、不重排章节**，也不把规定留在下一章的细节提前塞进本章。

## 二、从 `materials.md` 到 `manuscript.md`

每章的 `materials.md` 已经按大纲小节分好三类内容，写作时按用途处理：

- **可写的技术要点** → 组织成连贯的技术解释。讲清成立条件、状态变化、设计取舍与失败边界，避免按材料条目逐条缩写。
- **可直接排入正文的素材** → 将字段表、对比表和 `assets/` 中的配图排入对应小节。
- **仅供作者核对的底稿** → 源码行号、commit 与具体 test case 地址用于写作者核对事实或生成 `[S01](../../sources.md#s01)` 引用，不要原样塞进面向读者的字段表。

## 三、让图文共同解释

- **章内相对路径**：由于 `manuscript.md` 位于 `chapters/<id>/manuscript.md`，引用本章图片直接写 `assets/fig-01-01.svg`，引用根目录公共来源写 `../../sources.md#s01`，引用另一章写 `../02-xxx/manuscript.md#anchor`。
- **图前带读、图后推论**：图前交代读者该看哪个结构、箭头或状态变化；图片独占一个 Markdown 段落，使用具体描述性 `alt` 作为题注；图后解释变化为什么发生、有哪些简化或边界条件，不重复抄写图内标签。
- **忠实于证据边界**：区分源码事实、文档声明、运行观察、推断与未知。发现核心证据或图片缺口时，在 `writing-review.md` 和 `book.json` 的 `core_gaps` 中登记，不靠常识编造项目细节。

## 四、统稿与自检

全书各章写完后，连读各章衔接处与 `outline.md`：

1. 检查每节是否兑现了 `outline.md` 要求讲清的内容与例子位置。
2. 对照 [writing-style.md](writing-style.md) 清理引导式问句标题、生硬翻译与空泛套话，确保必要英文术语、代码块、数值、单位和限定条件准确保留。
3. 在 `writing-review.md` 简要记录统稿情况、图文核对结果与未验证项，将 `<!-- r2b:pending -->` 更新为 `<!-- r2b:reviewed -->`。
