# 写成一本书，而不是加工一叠笔记

## 学习顺序与叙事

先从 plan.md 理解全书主线，再给各章安排承接点和具体例子。
材料给事实，作者负责组织：哪些先讲、哪里需要一个反例、哪个图能替代一段抽象描述。
章节大纲可以改得更适合阅读，但不能凭文字修辞制造研究没有证明的因果。

每章围绕一个主要问题推进。推荐顺序是一个具体困境/输入 → 图中变化 → 机制 → 源码落点 → 取舍与边界。
这是思考方法，不是固定小标题。概念章、实现章、边界章不必同构。
每段推进一个意思；术语第一次出现解释；读者可以在正文中理解而不必跳到底稿。

## 以图为中心，但不让图替代证据

图前说明“看什么”，图后带读“发生了什么变化、为什么这样、什么时候不成立”。
总览图与细节图之间清楚说明抽象层级；重复对象保持同名同义。
已有图的标签和解释冲突时先核对材料，不擅自重画证明自己观点。
引用概念插画时保留其示意属性；不能称实际硬件、真实实验、精确内存布局。

将图单独放成 Markdown 段落，使用包内相对路径；alt 是具体题注。
保留 SVG/位图和编辑源，不能只留下图的链接或聊天附件 id。
需要新图则给研究阶段一个具体补图问题，不默认要求写作模型有绘图工具。

## 证据与边界

来源引用示例：`[S01](../sources.md#s01)`；各来源锚点由研究包固定。
引用具体函数/行号时保留源码版本语境。必要的代码摘录短、可解释，不把代码清单当书。
如果原始研究只是静态分析，作者不能改成“运行证明”；如果只是作者推断，不能改成项目设计动机。
说明来自论文的通用机制与项目代码实现是否相同，尤其是支持范围和默认配置。

定量结论保留单位、硬件、配置、负载、测量/推导方法。缺一项影响解释时回到材料问缺口，
不通过“显著”“极致”“几乎没有代价”掩盖缺失。

## 串联与自查

连读章首检查主线；看章末是否自然接下一章而非重复目录预告。
统一术语、图号、例子和抽象层级；删重复材料，不平均用力。
“读完能做什么”用复述机制、追踪一个输入、定位源码或判断变更影响来检验。
提出理解问题不等于真实读者已经理解；不要把模拟读者自查称用户验收。

代表性章先校准；除非用户要求审批，不每章停下来询问。
完成 agreed scope 后再统稿与排版，不因为一次回复长度限制把全书压缩成摘要。
