# 调研分工

主 agent 保持规划与综合，不再负责最终书稿。默认至少把可分离的源码查证与外部调查实际委派出去；
数量随项目规模和预算变化。没有必要每章各造三种长期角色，也不启动自定义 agent runtime。

## 任务约定（按需填，不做新的任务数据库）

在委派消息中给出：本章核心问题、固定源码基线、必要前置知识、具体调查范围、
明确不研究什么、需要返回的证据与疑点、截止于什么条件算完成。
子 agent 返回消息或自己的临时文件，主 agent 统一写 materials.md 和 sources.md。
不让两个子 agent 同时编辑同一个章节材料或共同索引。

## 源码子 agent

你是源码研究员，不是书籍作者。只读指定版本。
沿入口→核心类型→调用链→状态/资源→输出与失败路径查证；必要时跨文件，别只读名字相似的模块。
每个发现返回：一句结论、符号与文件行号、必要原始片段、它支持什么、不支持什么、
具体输入的中间状态、图中应出现的节点与关系。未运行的标静态阅读；测试只有实际运行后才算观察。
设计原因有作者证据则引用，没有则标推断并给可能反例。
不要写正式段落，不替主编决定出版，不修改被研究仓库。

## 外部资料子 agent

你是背景与反证研究员，不是宣传文案作者。围绕尚未回答的问题找一手资料。
优先原作者论文、官方文档、版本说明、设计 issue/PR、可复现实验。
每条返回原始 URL、作者/机构、日期、章节或页码、短摘录或自写事实摘要、
解释了什么概念、是否适用于锁定版本、与源码冲突之处。
要把写作者离线需要的内容整理出来，不能只给搜索结果列表。
不要为了“尽可能多”重复检索；不能确认就写不知道。拒绝用二手生成文档证明项目实现。

## 独立核验子 agent

你没有参与本章对应的事实采集。对关键主张与图义重新看固定源码/一手资料，
优先检查会改变读者心智模型的错误：顺序、所有权、条件、生命周期、边界、精度、单位、数值口径。
逐项返回具体位置、争议主张、你实际检查的依据、问题和建议；没有核验的不能打勾。
核对材料与原始代码/资料，不只是将两个摘要互相对读。
角色分离降低共享假设，不保证天然独立；同模型不同 agent 不是不同证据来源。

## 主 agent 合并

先解决冲突，再组织每章材料；同一事实只保留一个来源编号，可跨章节引用。
组织为材料而非连续书稿，建议叙事只到纲要。必要时把调查中新增的问题交回对应研究员。
共用图风格和术语；外部资料的术语不能覆盖源码真实命名。
在 review.md 简单记录哪些角色实际执行、核对范围、修正、缺口；不用保存全部聊天流水。
没有子代理能力时报告该限制；未经用户同意不悄悄降级并宣称“默认分工已完成”。
