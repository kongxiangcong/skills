# 从项目到逐章研究素材

## 开工能力核对

侦察和初步配图计划后、深入逐章研究前，仅核对本计划实际需要的能力：读取固定源码与必要一手资料、子代理委派与独立核验、diagram-design 导出、适用时的内置 imagegen、真实图片文件的保存方式、必要的预览环境。
核对工具是否实际可调用、产物能否落到交接目录；不要只凭工具名称假设能导出文件。
已有用户授权的替代方式直接沿用，不重复询问。缺工具时列明受阻章节/图/核验项，继续独立工作；只将受影响项保留 draft，不把工具限制伪装成内容不需要。
某章核心缺证不阻塞其他独立章节；完整交接仍等待核心缺口解决。所需能力与实际结果在 review.md 简短记录，不另建能力数据库。

## 规划

锁定完整 Git commit；工作树改动记录差异，无 Git 时记录文件 SHA-256。先读 README、构建入口、核心类型、代表调用链和测试。
在 plan.md 写明读者、目标、范围与不研究什么、章节问题/依赖、配图计划；目录变更说明原因。

读者目标决定深度，运行主线决定顺序，代码证据决定内容。先侦察，再给可修订目录。
每章说明一个主要问题、前置知识、读完应能做出的解释/动作、关键源码范围和配图意图。
原理章、机制章、边界章可以有不同结构，不按固定章数或文件数凑完整。

对编译器/NPU/模拟器，优先追踪一个真实输入穿过 IR、映射/调度、存储、描述符与执行；
不把所有组件名列出来就称系统完整。一般软件项目选择自己的端到端输入输出路径。

## 证据到材料

源码事实：仓库 + 完整 commit（或本地哈希）+ 路径 + 符号 + 行号 + 必要片段。
文档声明：原作者/机构 + 原始 URL + 版本/日期 + 原件位置 + 自写摘要。
运行观察：实际命令、输入、环境、输出和未覆盖范围。教学模拟要标明，不冒充原系统测量。
推断：来自哪些事实、怎么推到结论、适用条件、可能反例。未知：看过什么、还缺什么、影响哪章。

长源码与外部资料可以按许可保存在 evidence/；默认只保存写作必需的片段/摘要。
同一来源共享编号，不按章重复收集。不同版本矛盾不能硬凑成一套行为。
外网查询只使用允许公开的词；不自动上传私有源码。转交其他模型前提醒用户确认材料授权。

## 逐章深挖

以本章问题为中心，追踪控制/数据/资源三种关系，找一个具体输入走读和一个有意义的失败边界。
不强制每章都包含所有类型的关系。状态机没有实际分支就不要画出重试和回滚。
性能描述只有复杂度推导时写推导，不得给具体吞吐/延迟；定量图标明条件、单位及是否实测。

研究过程就画图，图中缺失的箭头含义、数据尺寸、所有权常常暴露研究缺口。
有缺口则继续查证，不等成稿后让写作者猜。先有来源，再将对应图义交给绘图工具。

停止条件是关键问题得到有依据的答案、主要路径连贯、冲突解决或有明确局限。
“搜索了很多”“达到字数”“用了多个 agent”都不能作为完成条件。

## 交接前

核对 plan 中全部计划章节在 research.json 中逐项列出，没有悄悄漏章。
每章材料离线能读懂，来源位置可复核；图稿已生成、查看且与材料一致。
review.md 区分独立核验、主 agent 自查与纯程序检查，记录实际执行，而非空勾选表。
ready 由执行者在事实与图片检查后声明；脚本只核文件和引用，不自动批准研究质量。
