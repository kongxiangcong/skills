# 从大纲确认到逐章研究素材

## 一、阶段一入口：讨论与锁定 `outline.md`

在开始重度源码深挖和制图前，先把写作意图和章节目录一起确认在根目录的 `outline.md` 中：

1. **轻量侦察**：锁定完整 Git commit（无 Git 时记录文件 SHA-256），快速浏览 README、构建入口、核心数据结构与代表调用链。
2. **编写或更新 `outline.md`**：
   - **全书约定**：明确读者是谁、读完应掌握什么、整体叙述顺序、术语偏好（保留必要英文术语，不强行翻译）、例子放置规则（例如“只在格式解释之后给例子”）、图表和文风要求。
   - **逐章大纲**：写明每章的作用、小节顺序、每节必须讲清的内容、需要哪张图或表，以及哪些细节留给下一章。所有章名与小节名直接陈述技术对象或机制（如“算子融合”、“描述符格式与字段对齐”），不使用引导式问题标题。
3. **停点等待确认**：当用户处于「讨论大纲」或调整目录阶段时，更新同一个 `outline.md` 后立即停下等待反馈，不生成第二套 `plan.md`，也不提前启动全书子代理调研。

## 二、阶段二入口：按确认版大纲调研备料

当用户明确表示「大纲可以了，按这版调研」或指定已确认的 `outline.md` 启动调研时：

### 1. 开工能力核对

仅核对本大纲实际需要的能力：读取固定源码与必要一手资料、子代理委派与独立核验、`diagram-design` 导出、适用时的内置 `imagegen`、真实图片文件的保存方式与预览环境。缺工具时列明受阻章节/图/核验项，继续独立工作；将受影响项保留 `draft`，在 `review.md` 简短记录。

### 2. 按大纲小节组织 `materials.md`

每章的 `chapters/<id>/materials.md` 直接沿用 `outline.md` 已确认的小节标题组织素材，不再维护第二套大纲。每个小节内部按三类用途归档：

- **可写的技术要点**：核心结论、成立条件、容易混淆的概念、必要的事实依据，以及穿过 IR、映射/调度、存储或描述符的具体输入走读与失败边界。
- **可直接排入正文的素材**：字段表、配图路径（`assets/...`）、题注建议，以及读者应从图中看出的关系。
- **仅供作者核对的底稿**：仓库完整 commit、源码文件路径、符号与行号、具体 test case 的内存地址或运行日志定位。明确标出哪些细节仅供写作者核对事实，不进入面向读者的正文或字段表。

源码事实、文档声明、运行观察、推断与未知保持严格区分。同一公共来源在 `sources.md` 中共享编号（如 `{#s01}`），跨章复用。

### 3. 事实细化与冲突上报边界

- **直接处理的事实细化**：字段位宽修正、补充成立条件、修正状态机分支条件、调整图中标签命名。
- **上报用户的结构冲突**：整节核心主张在源码中缺乏依据、发现必须更换某章的组织主线或推翻 `outline.md` 中已确认的编辑决定。此时将具体冲突交由用户确认，其余无依赖章节继续推进。

## 三、交接前检查

核对 `outline.md` 中的全部章节已在 `research.json` 中按顺序登记，每章 `materials.md` 与 `assets/` 配图齐备且可离线理解，`review.md` 如实记录独立核验、主 agent 自查与已知缺口。执行 `research.py check <专题目录>` 通过后，更新 `START_HERE.md` 并停止。
