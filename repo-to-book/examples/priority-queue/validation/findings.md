# 源码说明独立核验

核验输入仅为 `claims.md` 与指定的 `boltons/queueutils.py`；未读取其他代理笔记或会话。以下行号均指该源码。提交号仅为待核验文档提供的版本标签，本次未另行验证文件与远端提交的一致性。

## 1. 默认 PriorityQueue 使用堆后端，数组整体按优先级从高到低排序

**结论：不成立，混淆了两种后端。**

- 第 223 行明确绑定 `PriorityQueue = SortedPriorityQueue`，所以默认别名使用有序序列后端，而非堆。
- `SortedPriorityQueue` 的 `_backend_type = BList`（212 行），以 `insort(backend, entry)` 插入（218–220 行），以 `backend.pop(0)` 弹出（214–216 行）。`BList` 导入失败时才回退为 `list`（76–80 行）。因此不宜无条件把默认后端称为普通数组。
- 每个条目为 `[priority, count, task]`（132–138 行）；默认转换函数是 `-float(p or 0)`（104–105 行）。有序后端按条目升序维护，对正常数值而言对应转换后有效优先级的原数值从高到低，同级按计数升序。自定义 `priority_key` 时，不能直接宣称原始输入数值越大越先出队。
- 真正的堆实现是 `HeapPriorityQueue`，使用 `heappush` 和 `heappop`（192–204 行）。堆的内部列表不保证整体有序，只保证堆性质。

直接运行指定源码，向 `HeapPriorityQueue` 依次插入优先级 `4, 1, 3, 2`，其内部条目的优先级槽为 `[-4.0, -2.0, -3.0, -1.0]`，对应原始优先级 `4, 2, 3, 1`，足以反驳“堆数组整体有序”。同一操作下默认 `PriorityQueue` 的类型名为 `SortedPriorityQueue`，优先级槽为 `[-4.0, -3.0, -2.0, -1.0]`。运行采用 `runpy.run_path`，相对导入走文件内置回退路径；此例不对 BList 内部实现作推断。

建议改写：本版本默认 `PriorityQueue` 是 `SortedPriorityQueue` 的别名，使用有序序列；另提供基于堆的 `HeapPriorityQueue`。默认数值优先级越高越先出队，但堆后端的内部列表并不整体有序。

## 2. remove 从成员映射删除任务，并将共享 entry 的 task 槽标为 _REMOVED；物理条目可继续留在后端

**结论：成立。**

- `add` 创建一个可变列表，并把同一个 `entry` 放入 `_entry_map` 和后端（136–138 行），因此它们共享条目引用。
- `remove` 先执行 `_entry_map.pop(task)`，再执行 `entry[-1] = _REMOVED`（144–145 行）。它不调用后端删除操作，故在这两个内置后端中，成功调用 `remove` 本身会保留后端条目，只将其标为已删除。
- `_cull` 仅在后端首条目被标记时调用 `_pop_entry` 清理，并重复直到首条目有效或后端为空（147–156 行）；`peek` 与 `pop` 都先调用它（164、178 行）。这不是一次性扫描清理后端所有失效条目。
- `__len__` 返回映射大小（187–189 行），所以逻辑长度不包括这些残留条目。不存在的任务会因映射 `pop` 抛出 `KeyError`（140–145 行）。

该表述适合源码读者；可补充“后续访问队首时惰性清理”以说明生命周期。

## 3. 对正常可全序比较的优先级，同级按入队计数排序

**结论：成立，但应明确是转换后的有效优先级及每次 add 的计数。**

- 实际比较的优先级先经 `_get_priority` 转换（132 行），并不是直接比较原始输入。
- 每个队列实例创建独立递增计数器（111 行）；每次 `add` 取新计数并构造 `[priority, count, task]`（135–136 行）。两个内置后端分别用堆操作和有序插入比较该列表（198–204、214–220 行）。当有效优先级相等且比较行为正常时，列表比较使用第二槽计数，较早添加的有效条目先出队。
- 已有任务再次 `add` 时，先 `remove` 旧条目，再取得新计数（133–136 行）。所以它按本次添加的位置参与同级排序，不保留首次入队位置。直接运行 `add('a',1); add('b',1); add('a',1)` 后，弹出顺序为 `b, a`。
- 这项判断适用于文件提供的两个具体后端；不能外推到任意覆盖后端操作的自定义子类。NaN 或不一致的自定义比较不在“正常可全序比较”的前提内。默认浮点转换还可能使不同原始值成为相同有效优先级。

建议改写：两个内置后端对转换后相同、可正常比较的有效优先级，按每次 `add` 取得的递增计数决定先后，因此同级有效条目按最近一次添加的顺序出队。
