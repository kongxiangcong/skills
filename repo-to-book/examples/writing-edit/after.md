# 同一个键为什么还会重新计算

懂 Python 的读者可以把这里的缓存看作保留计算结果的地方。以下讨论假设版本 v1.2 的单线程行为，是教学假设，不是项目实测。本例不附源码，也不宣称复现；假设源码位置为 `cache/core.py`，依据 [S01]。

`get(key)` 命中时返回已有值，不调用 `compute(key)`。未命中时，它调用 `compute(key)` 并将结果存入缓存。因此，理解同键请求为什么重新计算，需要先判断请求时缓存中是否还保留着结果。

缓存最多保存 128 项。插入后若超出上限，会按插入先后移除最早插入的一项。命中不会改变插入顺序，所以这里的淘汰规则不是按最近访问时间决定的。即便一个键曾经命中过，它仍可能因最早插入而被移除，再请求时就需要计算。

清空也会让已有结果消失：`clear()` 清空所有项，下一次请求同键时会重新计算。容量淘汰与主动清空都应在理解未命中时一并考虑。

本例没有性能测量，不能给出加速比例；并发安全性未知。单线程行为不足以支持并发结论。
