# 真实工作流验收方法

自动测试验证接口与出版，以下验收验证模型行为，两者不可互相替代。实际已执行范围见 VALIDATION.md；方法存在不代表已执行。

## A：Codex 的真实研究分工与图片

选择规模适中、允许公开研究的实际仓库，给出读者目标和预算，启动 repo-to-research：

```text
使用 $repo-to-research。研究 <项目 URL/路径>，输出 ./research。
先侦察固定版本、规划全书，再默认委派源码和外部资料子 agent 逐章深挖。
使用 diagram-design 完成精确机制图、内置 imagegen 完成适合的概念插画，保存实际本地图片。
由独立子 agent 核验关键事实与图义。材料完整后导出并停止，不写正式正文、不出版。
记录真实工具与执行范围，缺工具不能伪称调用，不自动切换收费 API。
```

观察是否实际发生：主线来自源码而非文件树；子代理确实执行；资料含一手证据内容；
图不是提示词占位；根状态 ready 之前已看图及核对；阶段一最后没有 manuscript/ 和最终书籍。
imagegen 若无合适用途，记录内容理由；若工具不可用，这是能力缺口，不是语义性豁免。

## B：另一个模型独立写作

把 export 输出与单独 repo-to-write 技能包转到另一个平台，不转原聊天、原机器路径或整个源仓库。
确保内部素材允许交给该平台；不要自动上传。

```text
按 repo-to-write/SKILL.md 使用这份素材写中文图解技术书。
默认 HTML，保留完整图文源稿目录。不要重做源码/外网调研，也不要调用 Codex 或出图服务。
从 START_HERE 开始，逐章自主组织语言并使用本地图片；证据缺口明确记录，不自行补成事实。
```

有终端时运行 prepare → 写作 → check → build；纯聊天时逐章交付 Markdown，再由用户本地构建。
观察来源限定是否保留、章间是否连贯、图义是否准确、原始图文是否完整。
确认默认不触发 PDF 安装或浏览器下载。

## C：失败注入

先删一张实际图片：交接/prepare 应报缺失，不把 prompt 当图片。
把一章状态改 draft：不能交给阶段二作为完整包。
删除生成位图对应的 prompt 或图解 editable：检查应指出缺文件。
让外部工具不可用：记录失败，不宣称出图成功、不自动收费回退。
给写作者一个关键事实冲突：应退回具体缺口，而不是继续外网搜索或编造。

## D：核心缺口与返修恢复

在干净研究包的单独副本中删去某核心机制的证据内容，并删除/限制所有会泄露该答案的切片、图稿和说明；保留其他独立章节可写。不得只删除链接而仍在别处给出答案。记录注入变更，写作者只拿到该副本和写作技能，不看到注入方案和标准答案。

写作者应登记具体缺口、继续其他章节，不把 ready 当事实保证、不自行联网补证。
随后由独立研究步骤提供完整修复包。先保存已有 manuscript 的哈希，执行 refresh 比较和应用；证明原稿字节未被覆盖、受影响复核失效、旧产物被移除。
写作者接着基于补充证据修改受影响内容，保留未受影响原稿，完成重审、重建与实际查看，最后 check --delivery。

额外检查：部分稿 check/build 可通过；coverage 缺失、未说明删并、pending 复核或 open 核心缺口不能通过交付检查。独立审校另给含一处错误主张的材料，保存实际发现，不提前告知错误答案。

分别报告：独立上下文写作、不同模型写作、跨平台隔离。不能把同模型子代理称为另一厂商模型，不能把提示“不联网”称网络硬隔离。

## E：可选 PDF

仅在明确要求后安装 PDF 依赖，使用 --format pdf。
实际查看页码、大纲、中文、图、表与代码。文件生成不代表排版已验证。
